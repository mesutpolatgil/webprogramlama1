## 1. Web Nasıl Çalışır?

**Öğrenme çıktıları:**
- İstemciler (clients) ve sunucular (servers) ile bunların web'deki rolleri.
- Genel hatlarıyla DNS ve nasıl çalıştığı.
- TCP/IP, HTTP ve paketlerin (packets) amacı.
- Temel düzeyde HTTP sözdizimi (syntax).
- Yaygın HTTP yanıt kodları (örn. 200, 301, 403, 404 ve 500).
- Bir URL'nin temel bileşenleri (protokol, alan adı, alt alan adı, yol).

### İstemciler ve Sunucular

İnternete bağlı bilgisayarlara *istemciler* ve *sunucular* denir:

- **İstemciler:** Tipik web kullanıcısının internete bağlı cihazlarıdır (Wi-Fi'ye bağlı bilgisayar, mobil ağa bağlı telefon vb.) ve bu cihazlarda bulunan web erişim yazılımlarıdır (Firefox, Chrome gibi tarayıcılar).
- **Sunucular:** Web sayfalarını, siteleri veya uygulamaları depolayan bilgisayarlardır. Bir istemci web sayfasına erişmek istediğinde, web sayfası kodunun bir kopyası sunucudan istemci makinesine indirilir, tarayıcı tarafından işlenir (render) ve kullanıcıya gösterilir.

### Araç Kutusunun Diğer Parçaları

- **İnternet bağlantısı:** İnternet üzerinden veri göndermenizi ve almanızı sağlar.
- **TCP/IP:** İletişim Kontrol Protokolü ve İnternet Protokolü. Verilerin internet üzerinden nasıl seyahat etmesi gerektiğini tanımlar.
- **DNS:** Alan Adı Sistemi. Web siteleri için bir adres defteri gibidir. `mozilla.org` gibi bir ismi IP adresine çevirir.
- **HTTP:** Hiper Metin Transfer Protokolü. İstemcilerin ve sunucuların birbirleriyle konuşması için bir dil tanımlar.
- **Dosyalar:** Web siteleri iki ana tür dosyadan oluşur:
  - **Kod:** HTML, CSS ve JavaScript.
  - **Kaynaklar (Assets):** Resimler, müzik, video, Word belgeleri, PDF'ler vb.

### Peki Tam Olarak Ne Oluyor?

Tarayıcınızın adres çubuğuna bir web adresi yazdığınızda:

1. Tarayıcı DNS sunucusuna gider ve web sitesinin gerçek IP adresini bulur.
2. Tarayıcı sunucuya HTTP istek mesajı gönderir.
3. Sunucu isteği onaylarsa **200 OK** mesajı gönderir ve dosyaları paketler halinde tarayıcıya iletir.
4. Tarayıcı küçük parçaları bir araya getirerek eksiksiz bir web sayfası oluşturur.

### DNS Açıklandı

Gerçek web adresleri (URL'ler) aslında `192.0.2.172` gibi IP adresleridir. DNS, `mozilla.org` gibi okunabilir isimleri bu IP adresleriyle eşleştirir.

### Paketler Açıklandı

Veriler web üzerinden paket adı verilen küçük parçalar halinde gönderilir. Her paket şunları içerir:
- **Başlık (Header):** Sunucu ve istemci IP adresi, paket numarası vb.
- **Yük (Payload):** Pakette gönderilen asıl veri.

Verilerin paketler halinde gönderilmesinin nedenleri:
- Düşen paketleri yeniden istemek, tüm dosyayı yeniden indirmekten hızlıdır.
- Paketler farklı yollardan yönlendirilebilir, bu da iletimi verimli kılar.

### HTTP Temelleri

```
GET /en-US/ HTTP/2
Host: developer.mozilla.org
```

Yaygın HTTP durum kodları:
| Kod | Anlam |
|-----|-------|
| `200` | Başarılı |
| `301` | Kalıcı yönlendirme |
| `400` | Hatalı istek |
| `403` | Erişim yasak |
| `404` | Bulunamadı |
| `503` | Sunucu hatası |

### Bir URL'nin Bileşenleri

`https://developer.mozilla.org/en-US/` URL'sinde:
- `https` → Protokol
- `developer.mozilla.org` → Alan adı (domain name)
- `/en-US/` → Kaynak yolu (path)

## 2. Web Standartları Modeli

**Öğrenme çıktıları:**
- Web standartları ve üzerine inşa edildikleri temel ilkeler.
- Standart kurullarının (W3C, WHATWG, TC39, Khronos) nasıl işlediği.
- Ana web standardı teknolojileri ve birlikte nasıl çalıştıkları.
- Sunucu taraflı ile istemci taraflı dosyaların karşılaştırması.
- Web için en iyi uygulamalar (best practices).

### Web'in Kısa Tarihi

- **1960'lar:** ABD ordusu ARPANET ağını geliştirdi (internetin öncüsü).
- **1980:** Tim Berners-Lee (TimBL), bağlantılar (links) konseptini içeren ENQUIRE programını yazdı.
- **1989:** TimBL *Information Management: A Proposal* ve *HyperText* belgelerini yayınladı.
- **1990-91:** TimBL, World Wide Web'in ilk sürümünü çalıştırdı: HTTP, HTML, ilk web tarayıcısı.
- **1994:** TimBL, W3C'yi (World Wide Web Consortium) kurdu.

> **Not:** "Web" ve "internet" farklı kavramlardır. İnternet altyapıyı, web ise bu altyapı üzerindeki sistemi tanımlar.

### Web Standartları Nedir?

Web standartları, teknolojinin nasıl çalışması gerektiğini detaylandıran *spesifikasyonlar* olarak var olurlar. Bunlar yazılım mühendisleri tarafından tarayıcılarda uygulamak için kullanılır.

### Standart Kurumları

| Kurum | Sorumluluk |
|-------|-----------|
| **W3C** | HTML, CSS ve diğer web teknolojileri |
| **WHATWG** | HTML Yaşayan Standardı |
| **TC39 / ECMA** | ECMAScript (JavaScript standardı) |
| **Khronos** | WebGL gibi 3D grafik teknolojileri |

### Web Standartlarının Temel İlkeleri

1. **Açık (Open):** Katkıda bulunmaya ve kullanmaya açık; patent engeli yok.
2. **Erişilebilir ve birlikte çalışabilir (Interoperable):** Farklı tarayıcılarda tutarlı çalışır.
3. **Web'i bozmayın (Don't break the web):** Yeni teknolojiler geriye dönük uyumlu olmalı.

## 3. Tarayıcılar Web Sitelerini Nasıl Yükler?

**Öğrenme çıktıları:**
- HTTP yanıtında döndürülen farklı kaynak türleri.
- Farklı dosyaların tarayıcı tarafından nasıl bir araya getirildiği.
- Tarayıcının neden bazen düşmanca, ama aynı zamanda harika bir programlama ortamı olduğu.

### HTTP Yanıtlarında Hangi Dosyalar Döner?

- **HTML dosyaları:** Sayfa içeriği ve yapısı.
- **CSS dosyaları:** Stil ve düzenleme.
- **JavaScript dosyaları:** Etkileşimli davranış.
- **Medya kaynakları:** Resimler, videolar, ses, PDF, SVG.
- **Diğer dosyalar:** Word, PowerPoint, Open Office vb.

### HTML'in İşlenmesi (DOM)

Tarayıcı HTML'i ayrıştırarak **DOM ağacı** (Document Object Model) oluşturur:

```
<p>
  Let's use:
  <span>HTML</span>
  <span>CSS</span>
  <span>JavaScript</span>
</p>
```

DOM ağacı:
```
P
├─ "Let's use:"
├─ SPAN → "HTML"
├─ SPAN → "CSS"
└─ SPAN → "JavaScript"
```

### CSS'in Ayrıştırılması

Tarayıcı CSS'i ayrıştırır ve stil kurallarını HTML elementlerine uygular (**render tree**). Ardından sayfa ekranda çizilir (**painting**).

### JavaScript'in Yüklenmesi

- `async` veya `defer` öznitelikleri olmadan `<script>` etiketi sayfanın yüklenmesini durdurur.
- Modern yaklaşım: `<script defer>` veya sayfanın sonuna koymak.

## 1. Araştırma ve Öğrenme

**Öğrenme çıktıları:**
- Etkili araştırma metodolojileri.
- Bir öğrenme planı yapmak.
- Motivasyonu korumak.
- Plastik ördek ile hata ayıklama (Rubber ducking).
- Etkili problem çözme.
- Sürekli öğrenme zihniyeti.

### Yüksek Kaliteli Kaynaklar Seçin

Güvenilir web geliştirme kaynakları:
- [MDN Web Docs](https://developer.mozilla.org)
- [Stack Overflow](https://stackoverflow.com)
- [freeCodeCamp](https://freecodecamp.org)
- [Codecademy](https://codecademy.com)
- [Scrimba](https://scrimba.com)

### Etkili Arama Yapın

- Resmi dokümantasyona önce başvurun.
- Kaynakların tarihlerini kontrol edin (güncel mi?).
- Tek kaynağa güvenmeyin, çapraz referans yapın.
- Yapay zeka araçlarını (ChatGPT, Copilot) dikkatli kullanın; cevapları doğrulayın.

### Bir Öğrenme Planı Yapın

**Hedef ifadesiyle başlayın:**
> "İki yıl içinde profesyonel bir web geliştiricisi olmak istiyorum."

**Zaman planı örneği:**
```
- HTML/CSS temelleri → yaza kadar
- JavaScript temelleri → Aralık ayına kadar
- İlk proje → Nisan ayına kadar
```

### Plastik Ördek ile Hata Ayıklama (Rubber Ducking)

Bir sorunu çözmekte zorlandığınızda, problemi cansız bir nesneye (veya kendinize) yüksek sesle açıklayın. Problemi mantık çerçevesine oturtarak çoğu zaman çözümü kendiniz bulursunuz.

### Etkili Problem Çözme

**Problemleri parçalara bölün:**
```
"Basit iki sütunlu bir web sitesi oluştur" →
  1. HTML yapısını oluştur
  2. Temel tipografiyi ayarla
  3. Renk şemasını belirle
  4. Düzeni (layout) uygula
  5. Gezinme menüsünü uygula
```

## 2. İşbirliği ve Takım Çalışması

**Öğrenme çıktıları:**
- Takım arkadaşlarıyla işbirliği yapma.
- Faydalı sorular sormak ve yardım etmek.
- Çalışmanızı yayınlamak.
- Açık kaynak projelerine katkıda bulunmak.
- Başarısızlıktan korkmamak; onu bir öğrenme aracı olarak benimsemek.

### Başkalarıyla Çalışmak

Web geliştirme takımlarında işbirliği genellikle **Git ve GitHub** gibi sürüm kontrol sistemleri aracılığıyla gerçekleşir:
- Geliştiriciler projenin ayrı kopyaları üzerinde çalışır.
- Birbirlerinin kodunu gözden geçirir (**code review**).
- Yorumlar aracılığıyla değişiklikleri tartışır.

### Bir Topluluk Ağına Katılın

- MDN Discord sunucusu
- Frontend Developers Discord
- freeCodeCamp forumları
- Yerel meetup grupları (Meetup.com)
- Teknik konferanslar (confs.tech)

### Başarısızlık Bir Öğrenme Aracıdır

Hata yapmak geliştirme sürecinin doğal bir parçasıdır. Önemli olan:
1. Hatayı tanımlamak.
2. Nedenini anlamak.
3. Çözümü bulmak ve belgelemek.

## 3. İş Akışları ve Süreçler

**Öğrenme çıktıları:**
- Genel bir projenin büyük resmini görmek.
- Sektörel iş akışlarını anlamak.
- Araçları ve süreçleri etkin kullanmak.

### Tipik Web Geliştirme İş Akışı

```
1. Gereksinimler → 2. Tasarım → 3. Geliştirme → 4. Test → 5. Yayın → 6. Bakım
```

### Sürüm Kontrolü (Git/GitHub) İş Akışı

```bash
git clone <repo-url>      # Projeyi indir
git checkout -b yeni-dal  # Yeni dal oluştur
# ... değişiklikler yap ...
git add dosya.md
git commit -m "hafta-01: 404klup açıklama"
git push origin yeni-dal  # Push et
# → GitHub'da Pull Request aç
```

### Kod İncelemesi (Code Review)

- Kod incelemesi hataları erken yakalar.
- Takım içi bilgi paylaşımını sağlar.
- Kod kalitesini korur.
